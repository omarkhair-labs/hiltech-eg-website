# HILTECH Evidence / Claims Gate

Status: **MANDATORY**
Date: **2026-08-31**

The visual concepts created during art-direction exploration contain placeholder metrics, company logos, locations, certifications and project examples. They are not automatically approved production content.

## Core rule

A visual placeholder is not evidence.

Before a claim reaches production it must be classified:

### VERIFIED
Supported by a trustworthy HILTECH source, client material, contract, certification, approved company profile, or other clear evidence.

Action:
- may be used accurately

### SUPPORTED — WORDING REVIEW
There is a real basis, but wording/scale/context needs correction.

Action:
- rewrite precisely before publishing

### UNVERIFIED
Only appears in old marketing copy, AI visual exploration, or unsupported text.

Action:
- do not publish as fact

## Claims currently requiring explicit verification before use

Examples that appeared in visual concepts or existing/older copy:
- 20+ years in infrastructure
- 500+ enterprise deployments
- 50+ engineers/specialists
- 99.99% uptime
- 24/7 technical support/monitoring
- specific throughput/latency/pass-rate figures
- “world-leading” or similar superlatives

Do not ship these because they look good in a KPI strip.

## Client logos / project logos requiring verification

without evidence.

## Brands / suppliers / technology labels

A product brand appearing in HILTECH inventory is not automatically a formal “partner.”

Classify separately:
- stocked/sold product brand
- technology used
- authorized reseller
- distributor relationship
- certified partner
- official strategic partner

Only use the exact relationship that can be proven.

Brands seen in current/public catalog context include examples such as:
- Schneider Electric
- CommScope
- Panduit
- HPE / Aruba
- Leviton

Their presence in product inventory can support product/brand filtering; it does not by itself prove formal partnership status.

## Standards / certifications

Do not use ISO/TIA/EIA/IEEE badges merely as decorative trust icons.

For every badge:
- verify whether it is a company certification, project standard, methodology reference, product standard, or aspirational claim
- use the correct label

Example:
“built to TIA guidelines” is not the same claim as “TIA certified company.”

## Technical telemetry

Hero/H02/H10 may use technical-looking labels such as:
- wavelength
- loss
- link state
- trace state
- route
- throughput

Rules:
- factual company/performance values must be real
- illustrative visualization values must be clearly treated as illustration/system UI, not company performance claims
- no fake measured result inside a case study

## Work / case studies

Never invent:
- client name
- country/city
- project scale
- deployment count
- measured result
- product quantity
- performance improvement

If real project media exists but the client cannot be named:
- use anonymized environment wording
- keep verifiable scope/evidence
- remove identifying details

## AI visual assets

AI-generated visual concepts are allowed as:
- art-direction references
- moodboards
- scene/composition inspiration

They are not acceptable as:
- fake project photography
- fake product photography
- fake client evidence
- fake field documentation
- fake certification proof

Production should prefer:
- real project evidence
- accurate product imagery
- custom CG explicitly used as visualization
- technical diagrams
- real testing/trace media where available

## Evidence hierarchy

Strongest:
1. signed/approved client or company records
2. official certification/documentation
3. HILTECH internal approved project evidence
4. current authoritative product/manufacturer records
5. existing HILTECH public copy

Existing marketing copy alone is not enough for high-risk proof claims.

## Pre-merge checklist

Before merging any new public section containing proof:
- [ ] Every numeric claim classified
- [ ] Every client logo verified
- [ ] Every certification/standard label accurate
- [ ] Every project fact grounded
- [ ] Every product image matches the product
- [ ] Every relationship label (“partner”, “authorized”, etc.) is exact
- [ ] No AI concept artifact is presented as real evidence
