## Research conclusions

### 1. HILTECH should not look like a conventional IT company
Reject:
- stock server-room hero
- service-card wall
- generic “innovative solutions” language
- blue network globe
- random glowing particles

### 2. HILTECH should not become a cybersecurity clone
Reject:
- hoodie hacker
- matrix rain
- permanent glitch
- dark + neon as the entire identity
- abstract threat metaphors unrelated to HILTECH

### 3. Infrastructure itself is the imagery
The visual material should come from:
- fiber
- routes
- ports
- racks
- patch panels
- topology
- signal
- redundancy
- wavelength
- testing traces
- measurement
- verification

### 4. Cinema must be balanced with business truth
Reference equation:

`HackFirst atmosphere × NRG infrastructure storytelling × Shift5 enterprise discipline × Integrated Reasoning original visual system × Google Cloud engineering rigor`

### 5. Heavy is allowed; waste is not
The goal is not “keep it light” or “make it heavy.”

The rule is:

> Make it as rich as the idea deserves, then engineer the weight out.

## Anti-pattern matrix

Do not ship:
- neon-blue network globe
- stock server-room hero as the identity
- random glass/chrome forms
- 20 equal service cards
- long pinned sections with no narrative reason
- WebGL for decoration only
- particles without semantic meaning
- fake HUD data presented as company facts
- motion that hides weak static composition
- copied HackFirst glitch/security language
- copied NRG craft aesthetic
- copied Google visual identity

## Static-composition rule

Every section must still work as a strong screenshot with:
- motion disabled
- WebGL disabled
- video paused

Motion amplifies the art direction; it must not rescue it.
