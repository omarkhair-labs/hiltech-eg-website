# HILTECH Home Experience Spec — H01 to H12

Status: **LOCKED FOR PRODUCTION**
Date: **2026-08-31**

This is the canonical homepage sequence. AI concept images are reference checkpoints only; numbering or content inside generated images does not override this file.

## H01 — Engineered Signal

Purpose:
- establish the creative thesis immediately
- create the strongest cinematic moment
- position HILTECH as an engineered infrastructure company, not a generic IT vendor

Primary H01 statement:
**EVERY SIGNAL NEEDS A PHYSICAL PATH.**

Internal lifecycle:
**BUILD → ROUTE → TEST → PROVE**

The lifecycle is a state/motion rail, not the giant hero headline.

Visual behavior:
- dormant physical infrastructure environment
- one signal activates through a fiber/termination world
- typography and route line share the same spatial composition
- signal reveals the physical path
- camera begins to disclose system scale

Motion:
- authored clip/width/track typography reveal rather than generic fade-up
- signal pulse
- path trace crossing the composition
- text locks into final structure as the route becomes active
- first scroll carries the signal into H02 instead of fading the page out

Recommended implementation:
- Three.js/WebGL master scene
- GSAP/ScrollTrigger
- optional pre-rendered CG support for non-interactive atmosphere

## H02 — The Invisible Layer

Purpose:
- make connectivity visible
- explain the hidden physical layer behind normal digital operation

Visual:
- fiber macro
- strands / routes / signal movement
- technical labels only when they add meaning

Motion:
- signal travels through fiber
- path/wavelength/loss visualization
- H01 world transitions into a closer scale rather than hard-cutting

Rule:
Any displayed numbers must be real, clearly illustrative, or omitted.

## H03 — Component → System

Purpose:
- show scale and engineering continuity

Canonical progression:
`Connector → Cable → Patch Panel → Rack → Room → Data Center → Infrastructure`

Motion:
- scroll-controlled camera
- progressive scale reveal
- no carousel/card treatment for the core journey

This is one of the main real-time 3D scenes.

## H04 — What We Build

Primary solution environments:
- Networks
- Fiber
- Data Centers
- Assurance

Purpose:
- first explicit business explanation after the audience understands the system

Visual:
- each environment gets one strong visual state
- reduce cinematic intensity versus H01–H03

## H05 — Build → Route → Test → Prove

Purpose:
- signature HILTECH lifecycle
- center of the homepage story

Sequence:

### BUILD
Physical structure assembles.

### ROUTE
Paths activate and establish connection.

### TEST
The visual language shifts from cinematic to measurement.

### PROVE
Movement resolves into a verified state.

Rule:
Keep it concentrated. Do not stretch this into an unnecessarily long pinned sequence.

## H06 — Capabilities

Lifecycle:
`Blueprint → Procured → Installed → Tested → Validated`

Capability families:
- Design & Architecture
- Supply & Procurement
- Fiber Installation & Splicing
- Structured Cabling
- Data Center Deployment
- Testing & Certification
- Support/Maintenance only where verified as a real HILTECH capability

Purpose:
- explain what HILTECH physically does
- move from art direction into execution confidence

Motion:
- lighter GSAP choreography
- one connected lifecycle rather than a wall of unrelated cards

## H07 — Components / Products

Purpose:
- introduce technical commerce without breaking the narrative
- show that components are parts of systems, not a detached shop

Visual:
- exploded component/system view
- product categories connect to infrastructure roles

Potential categories, subject to real catalog validation:
- Fiber
- Copper / UTP
- Connectivity
- Fiber Management
- Cabinets / Racks
- Network Hardware
- Testers / Tools
- Accessories

Interaction:
- explore category
- browse products
- direct product lookup must remain fast

Rule:
A procurement user must never be forced through cinematic interactions to buy/find a part.

## H08 — Technology / Partners

Purpose:

Visual:
- calm

Content:
- only verified brands/partnership relationships
- distinguish “products we sell/use” from formal “partner” status

## H10 — Validation

Purpose:
- convert the early cinematic signal into measurable proof

Visual:
- pulse travels through fiber
- return/reflection appears
- OTDR/measurement trace forms
- system states become verified

Narrative:
`Invisible → Visible → Measurable → Proven`

This is a key brand moment and should be one of the strongest sections.

Implementation:
- Rive/SVG/GSAP for diagrams when sufficient
- WebGL only if spatial behavior materially improves the explanation

## H11 — Certainty

Purpose:
- release visual tension
- communicate standards, reliability, assurance

Behavior:
- almost no camera travel
- no visual storm
- restrained composition
- strong whitespace / precision

Content:
- only verified standards/certifications/process claims

Narrative state:
**CERTAINTY**

## Homepage rhythm

The page must alternate intensity:

`Cinema → Technical document → Spatial scene → Calm explanation → Signature motion → Precision → Commerce → Trust → Evidence → Validation → Silence → Conversion`

Avoid:
`card wall → card wall → card wall`

## Visual intensity by surface

- Home: 100
- Solution landing: 80
- Work/Case: 75
- Capability: 55
- Company: 40
- Product category: 25
- Product detail: 15
- RFQ/Cart: 5

## Copy direction

Avoid generic corporate claims.

Prefer short, technical, declarative copy.

Brand voice:
- Precise
- Kinetic
- Engineered
- Assured

Machine/system voice:
- mono labels
- measurements
- port/link/trace/state metadata

Examples of system-style labels:
- PORT 24 / ACTIVE
- LINK / VERIFIED
- OTDR TRACE / PASS

Do not use fictional telemetry as company proof.
